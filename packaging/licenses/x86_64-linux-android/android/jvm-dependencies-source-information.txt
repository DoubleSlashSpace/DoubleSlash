Android JVM dependencies — license information
==============================================

What is shipped
---------------
The APK bundles the Java/Kotlin libraries below: AndroidX, Jetpack Compose,
CameraX, the Kotlin standard library and coroutines, and their transitive
dependencies. They are packaged as classes inside the APK's dex, not as
separate files, so this file is where their notices live.

Why this file exists
--------------------
The Android Gradle Plugin's default packaging rules exclude META-INF license
and notice files from the APK. A build of this app was inspected to confirm
it: of 58 META-INF entries, every one was a `.version` marker and none was a
LICENSE or NOTICE. The `merges` rule in android/app/build.gradle.kts only
applies to paths that survive those excludes, so it does not put upstream
notices in the package. Without this supplement the JVM dependencies would
ship with no license text at all.

Licenses
--------
Every artifact below is Apache-2.0 except where the table says otherwise.
The full text ships beside this file as apache-2.0.txt.

androidx.camera:camera-core additionally declares a BSD license: it embeds
libyuv for frame conversion. That text ships as libyuv-LICENSE.txt, which
carries the copyright notice and disclaimer its terms require to be
reproduced in binary redistributions.

Two artifacts declare no <licenses> block in their POM,
com.google.auto.value:auto-value-annotations and
com.google.guava:listenablefuture. Both are Apache-2.0 upstream; they are
listed as "not declared in POM" below rather than silently relabelled.

How this list was produced
--------------------------
Resolved with

  ./gradlew :app:dependencies --configuration releaseRuntimeClasspath

and each artifact's declared license read from its POM in the Gradle module
cache. The list is pinned to the versions in gradle/libs.versions.toml at the
revision recorded in inventory.json. Changing a dependency version, or adding
one, means regenerating this file — nothing detects a stale entry.
